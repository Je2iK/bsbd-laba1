## 📌 Архитектура и стек

* **СУБД:** PostgreSQL 16 (Alpine) в изолированном Docker-контейнере.
* **Миграции:** `golang-migrate/migrate:v4.17.0` (версионированные `.up.sql` и `.down.sql`).
* **Разделение схем:**
  * `ref` — нормализованные справочники (уровни доверия, типы документов, биометрические модальности, ведомства-потребители).
  * `app` — ядро бизнес-сущностей (граждане, цифровые профили, электронные паспорта, биометрические шаблоны, согласия, токены).
  * `audit` — журналы безопасности (`data_change_log` с JSONB-снимками DML, `login_log` с фиксацией пользовательских сессий).
  * `stg` — буферная таблица для пакетной загрузки.
* **Безопасность:**
  * Отключение публичных прав (`REVOKE ALL ON DATABASE/SCHEMA FROM PUBLIC`, `ALTER DEFAULT PRIVILEGES`).
  * Роли разделения обязанностей (SoD): `app_reader`, `app_writer`, `app_owner`, `auditor`, `ddl_admin`, `dml_admin`, `security_admin`.
  * Логин-пользователи с параметром `NOINHERIT`.
  * Принудительный построчный контроль доступа: `FORCE ROW LEVEL SECURITY` на ключевых таблицах с проверкой уровня доверия (`Trust Level`) и идентификатора гражданина.
  * Шифрование чувствительных данных (*Restricted*): биометрические векторы и образы чипов электронных паспортов зашифрованы алгоритмом AES с использованием модуля `pgcrypto` (`pgp_sym_encrypt`).
* **Оформление отчёта:** строгий ГОСТ 7.32–2017 в [Typst](https://typst.app/) и Microsoft Word (`.docx`).

## 🚀 Быстрый старт (Makefile)

Все операции развертывания и тестирования автоматизированы через `Makefile`:

```bash
# 1. Запустить контейнер PostgreSQL
make up

# 2. Применить все миграции базы данных (схемы, таблицы, роли, RLS, сиды)
make migrate-up

# 3. Запустить проверочные сценарии прав и RLS (прогон тестов)
make test

# 4. Войти в интерактивную консоль базы данных
make psql

# 5. Собрать отчёт в PDF (по ГОСТ 7.32)
make report

# 6. Сгенерировать отчёт в формате Word (.docx)
make docx

# 7. Остановить контейнеры
make down
```
